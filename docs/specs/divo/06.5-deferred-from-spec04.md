# 06.5 — Deferred work backlog (specs 04–06)

The single backlog of everything specs **04** (outcomes/DoD/governance), **05** (dream seam), and
**06** (roles & workforce) define but haven't yet implemented. It changes no design — it records
what's left, why, and what unblocks each item.

Originally this tracked only spec 04's deferrals "until after spec 06." Specs 05 and 06 have **now
landed** (the dream-seam failure contract; the roles/overlay/registry/GitWorkforce/invokability
substrate), so this doc is re-scoped to the live cross-spec backlog. Most remaining items are no
longer blocked on *missing infrastructure* — the substrate exists; what's missing is the **runtime
wiring** that makes roles actually generate DoDs, route reviews, and enforce caps.

## §1 — DoD: what's left

| Item | Status | Unblocked by |
|---|---|---|
| **DoD auto-generation at intake** (`dod_generator`) | deferred | **spec 10 §5** intake seam (`submit()` is a stub) — role substrate ready |
| **AgentReview enforcement** (judgment gate) | deferred | wiring only — **Reviewer role now landed** |
| **Ladder rung 2** (reviewer escalation → `in_review`) | deferred | wiring only — Reviewer role landed |
| **DoD revisability** (tighten / loosen, `dod.revision`) | deferred | self-contained core; manager-authority via spec 06 (landed) |

**Auto-generation at intake.** The role's `dod_generator` (defined on every `Role`) is **never
called** — it would be called by `Chorus.submit()`, which is itself a stub
([facade.py:120](src/chorus/facade.py:120), `raise NotImplementedError("spec 10 §5: intake stub")`).
So today a task has no DoD unless one is set manually (CLI / ledger). The substrate is ready; the
**intake door** that drives it is spec 10 §5 (horizon).

**AgentReview + rung 2.** The Reviewer role and the `AgentReview` verifier now exist, and the FSM has
an `IN_REVIEW` state — but nothing transitions an `AgentReview`-DoD task into review or wakes a
Reviewer to render a verdict. `_land_passed` only handles `HUMAN_APPROVAL`
([_scheduler.py:367](src/chorus/heartbeat/_scheduler.py:367)). This is now pure wiring (no missing
substrate): route an `AgentReview` landing → `in_review` → Reviewer beat → verdict back onto the
`dod` row; rung 2 of the ladder opens that same path when the repair budget is exhausted.

**DoD revisability.** Revisioned `dod` with audited tighten/loosen (loosening needs the artifact
class's approval), in-force-at-evaluation rule. Manager-authority concept now exists (spec 06); the
ledger mechanics are still to build.

## §4 — Trust (fail-closed presets): what's left

**Entirely deferred.** The pure-chorus core is self-contained; enforcement needs a **dream** change.

| Item | Status | Unblocked by |
|---|---|---|
| `TrustPreset` model (`standard` / `low_trust_review`) | deferred | self-contained |
| **Fail-closed layered resolution** (intersect employee/task/run; narrower wins) | deferred | self-contained |
| Boundary scope (task-in-boundary, secret-ref allow-list, no inline secrets) | deferred | self-contained |
| **Resolved preset → dream `permissions` Policy + `sandbox` + role toolset** (per beat) | deferred | **dream** (per-task policy) |

dream's trust is **per-harness** (`build_harness(permission_mode=…)`); `run_task` takes no per-task
override. Applying a *task's* resolved preset needs either a dream change (per-task policy arg) or
chorus running one harness per preset and routing each beat. Note: the **manifest overlay**
([roles/_overlay.py](src/chorus/roles/_overlay.py)) already does monotone capability *narrowing* at
the role layer — the trust resolver layers task/run policy on top of it. Invariant to preserve:
**containment ≠ privacy** (low-trust limits API read/mutate + blocks untrusted-output promotion; it
must not hide work from the board).

## §5 — Governance: **shipped** (dev/m3-governance, Approach A)

All four governed actions + the third resolution now land via a generalized governed-action queue —
see [full-manager/GOVERNANCE.md](../full-manager/GOVERNANCE.md).

| Item | Status |
|---|---|
| **`hire_employee`** governed action | **done** — `EmployeeStatus.PENDING` (uninvokable) + `HireEmployeeAction` (approve→active, deny→terminated); `Chorus.request_hire` creates the pending employee + budget, gated by policy |
| **`plan_approval`** (approve a manager's decomposed plan) | **done** — `PlanApprovalAction` (approve releases children, deny cancels + recovery card, revise re-plans); `GovernanceResolver.open_plan_gate` holds the freshly-decomposed children |
| **`board_approval`** distinct flow | **done** — `BoardApprovalAction` (approve→`promoted` activity on the artifact, revise→wake the author); `Chorus.request_promotion` gated by artifact class |
| **`revision_requested`** approval status | **done** — `ApprovalStatus.REVISION_REQUESTED` + `ApprovalDecision.REQUEST_REVISION`; every handler implements `on_revise` |

The seam: one `ApprovalAction` column (migration 0015) + a `GovernedAction` handler registry + a thin,
atomic, audited `GovernanceResolver` dispatcher + a fail-closed `GovernancePolicy` for auto-open. The
empty default policy gates nothing, so the change is backward-compatible. `examples/governance_suite.py`
→ `reports/m3-governance.html` exercises all four actions + `revision_requested`.

## Build order when this batch is picked up

The substrate is in place, so most items are now wiring rather than new subsystems:

1. **Spec 06 §4 depth-cap enforcement** — smallest, self-contained, and closes a shipped-but-unenforced gap. Check `request_depth` vs the cap before `decomposition_claim` opens; fail closed (block + `recovery_action`).
2. **§1 AgentReview + ladder rung 2** — route `in_review` to the Reviewer role, record the verdict (substrate ready).
3. **§2 landers + kernel `land()`** — Engineer lander first (PR/CI), then Reviewer/PM/Analyst; + metadata canonicalization + `workspace_file` safety.
4. **§5 `hire_employee`** — add the employee `pending` state + activate/terminate; then `plan_approval` / `board_approval` + `revision_requested`.
5. **§1 DoD revisability** — revisioned `dod` + tighten/loosen authority.
6. **§4 trust** — preset model + fail-closed resolution (chorus-only) first; then the dream wiring once the per-task-policy decision is made.
7. **§1 auto-DoD at intake** — lands with **spec 10 §5** (the `submit()` intake seam / horizon), which calls each role's `dod_generator`.

Items 1–6 are chorus-only with today's substrate. Item 7 waits on spec 10's intake door; §4's
enforcement half is the only piece that also needs a dream change.
