4 · Manual code review — beyond the DoD floor

Every source and test file Finn shipped for shop was read line by line. The goal was to confirm the code is genuinely correct and honest — not merely enough to satisfy an automated gate. Findings below; no defects were found.

src/cart/cart.ts correct

Pure reducer + selectors, no React import. add merges and clamps quantity 1–999; remove filters; setQuantity clamps 0–999 and removes at 0; clear resets. getCartItemCount sums quantities; getCartTotalCents uses a price map and safely ignores unknown ids; formatMoneyFromCents uses toLocaleString USD. parseLines defensively validates untrusted localStorage (type checks, clamps, de-dupes by id keeping last). Clean pure/view seam — the reason the logic is unit-testable.

src/cart/CartProvider.tsx correct

useReducer with a lazy initializer that loads from localStorage (SSR-guarded via typeof window === 'undefined'); a useEffect persists on every state change; the context value is useMemo-ed; useCart throws when used outside the provider. Matches the react-doctor guidance on effects and stable context.

src/App.tsx & src/main.tsx correct

CartProvider wraps the whole app (one shared cart). CartSummary reads the cart and sits in the header outside <Routes> — so the live count + total are visible on every view. Routes cover /, /product/:id, /cart, and a * not-found. main.tsx uses BrowserRouter (HTML5 history → real back/forward + deep links) inside StrictMode. Accessible: aria-labels on the cart summary, count, total, and primary nav.

src/routes/{ProductList, ProductDetail, CartView}.tsx correct

List maps products to accessible "View details" links. Detail looks up by useParams id and handles not-found (deep-link safe) with an add-to-cart and a live "Cart now: N items" line. Cart view has an empty state, keyed line items, a labelled quantity input (min 0 / max 999, 0 removes), Remove and Clear-cart buttons — proper <label htmlFor> wiring throughout.

src/cart/cart.test.ts 9 genuine tests

Behaviour-focused unit tests: add-new + increment, remove, setQuantity set + remove-at-0, item count, total (verifying unknown ids are ignored), money formatting, and storage round-trip incl. invalid/empty payloads. They test observable behaviour, not implementation detail.

tests/storefront.spec.ts 2 real e2e tests

Test 1 walks the full journey: deep-link /product/p2 → add → assert count 1 / $24.99 → cart → set qty 2 → $49.98 → remove → $0.00 → products → open Arc Mug → add → $15.99 → goBack (cart persists) → goForward (cart persists) → deep-link /cart (cart persists). Test 2 seeds localStorage before scripts run and cold-starts at /cart, asserting the seeded cart loads (2 / $49.98). Uses web-first role/label queries and asserts exact totals — so it catches real arithmetic and routing regressions.

playwright.config.ts & package.json correct

Playwright serves the built app (npm run build && vite preview) on a fixed port, chromium project, reuseExistingServer: !CI. package.json scripts are honest and CI-safe (test = vitest run src), dependencies are minimal and appropriate.
