What Was Run

The experiment started from a clean seed repo named Stellar Pantry. One Engineer was hired and assigned 12 small tasks one by one: README, Python package model, storage, summary helpers, CLI commands, JSON data, tests, operations docs, and report rendering.

Each task included the same memory requirement: search project memory for experiment-conventions, fetch it with memory_get, append working memory, and read working memory back. Each task also had an explicit command verifier that was run again against company main after landing.

Raw outputs are under .chorus/engineer-long-run-fixed-20260618/: results.json, tool-log.jsonl, chorus-events.jsonl, the SQLite ledger, isolated Dream home, and the final company work repo.

Answer: Do Worktrees Merge After Task Completion?

Yes. Passed Engineer beats land through EngineerLander, which snapshots the employee worktree and calls CompanyWorkspace.merge(). The merge path creates a merge commit into company main and records a PR-style artifact with merged: true.

The long-run found an important edge case: Dream sometimes checked out a task branch inside the employee worktree. Before the fix, Chorus snapshotted the current branch but still merged chorus/employee, so later artifacts said merged while main stopped advancing. The fix makes CompanyWorkspace._snapshot() fold the current worktree branch back into chorus/{employee} before the lander records and merges it. The final run confirmed the worktree branch was chorus/employee after every task and all 12 post-merge checks passed on main.
