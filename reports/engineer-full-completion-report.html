High-Level Design

Chorus remains the organization and ledger plane; Dream remains the execution layer. The seam is still one beat: materialize the role-faithful Dream harness in an employee worktree, run dream.run_task, convert the result to a BeatOutcome, and durably land ledger state plus typed events.

Operator / CLI
    -> SQLite ledger: employees, tasks, wakes, runs, recovery
    -> Scheduler: claims one wake per employee and dispatches a beat
    -> EmployeeHarnessFactory: writes role overlays/sandbox in the worktree
    -> Dream harness: tools, skills, memory catalogue, MCP, plugins, evaluator
    -> DreamObserverBridge: converts Dream run events to Chorus Event envelopes
    -> EventBus / FanoutBus: live render plus durable events.jsonl
    -> Inspector: reads ledger + events.jsonl to answer working vs stuck

The spec now explicitly separates what is already implemented in Dream from what belongs in Chorus. Hooks stay gated because Dream has no direct hooks= factory knob; plugins, MCP, skills, memory, and event streams are treated as existing Dream execution-layer surfaces that Chorus should wire rather than reimplement.

Low-Level Design

ComponentContractImplementation Detail
EventBus emit(Event), subscribe(callback), replay(after=None) Serializes one typed envelope per line with kind, at, entity refs, and JSON payload. Replay reconstructs EventKind and datetime.
FanoutBus emit(Event) Forwards events to each sink. Sink exceptions are isolated so observability failures never fail a beat.
Tick wiring Scheduler(event_bus=EventBus(...)) Writes .chorus/work/company/events.jsonl for autonomous heartbeat/tick beats.
Chat wiring Scheduler(event_bus=FanoutBus(render_bus, EventBus(...))) Keeps current live chat rendering while adding the same durable log spine.
Spec plan Engineer-full build slices Sections now state exact Dream support and identify only true gates: first-class hooks and memory scope partitioning.
