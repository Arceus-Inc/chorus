A. Deliverable flaws — the tinyvec deliverable (7)

Defects in what the org actually produced — is it a real, usable, distributable artifact?

1The implementation and its own test file disagree on the public APIAPI-SPLIT-BRAIN
lib.rs exposes TinyVec::new(dim) + query(q, k, metric) — the metric is chosen PER QUERY. tests/bruteforce.rs calls TinyVec::new(dim, Metric::Cosine) + query(q, k) — the metric is fixed AT CONSTRUCTION. These are two incompatible API designs: the impl-author put the metric on the query, the test-author put it on the constructor, and integrate merged both without reconciling. This is the split-brain in its purest form — except here it's between a module and its own tests.
2cargo test does not compile (rc=101)TEST-BROKEN
Direct consequence of the API split-brain: `cargo test` fails with error[E0061] — 'this function takes 1 argument but 2 arguments were supplied' (the new(dim, Metric) calls) and 'this method takes 3 arguments but 2 arguments were supplied' (the query(q, k) calls), repeated across every test. Crucially `cargo build --release` PASSES (the library compiles in isolation), which masks that the test target is broken. A build-only gate would have called this green.
3The HNSW-style ANN index — the core deliverable — is absentMISSING-ANN
The brief required a navigable-small-world (HNSW-style) approximate index whose recall is asserted against brute-force. lib.rs is PURE BRUTE FORCE: top_k() iterates every vector, scores it, sorts, truncates. There is no graph, no index, no approximate search. The entire point of the task (ANN beats brute-force on speed while matching it on recall) is not implemented — and therefore the recall-vs-brute-force comparison the brief asked for cannot exist.
4bincode disk persistence is absentMISSING-PERSIST
The brief required bincode disk persistence (save/load). Cargo.toml's [dependencies] section is EMPTY — no bincode, no serde. lib.rs has no save/load, no serialization of any kind, no disk I/O. A second of the four headline deliverables is simply missing.
5The entire target/ build cache is committed (~1.4 MB)TARGET-COMMITTED
git tracks target/debug/, target/.rustc_info.json, *.rmeta, and the incremental build cache — dep-graph.bin (861 KB), query-cache.bin (496 KB), fingerprints, lockfiles. There is no .gitignore. Rust build output must never be committed; this is the Rust analog of the harness-artifact leak, but it is the crate's own compiled cruft.
6A Python smoke test sits in a Rust crateSTRAY-PY
test_smoke.py (`def test_smoke(): assert True`) — a PYTHON file — is committed at the root of a Rust crate, leaked from the harness seed. Nothing runs it (cargo ignores it). Alongside it, 22 harness-internal files leaked (docs/evals/*.json, docs/exec-plans/*).
7README is the seed stubREADME
README.md is 15 bytes: '# company repo'. None of the four required features (metrics, ANN index, persistence, query API) are documented, and there is no build/usage guidance.
