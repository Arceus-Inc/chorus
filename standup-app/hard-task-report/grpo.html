Hard-Task Flaw Report

GRPO Tune — a Python library wrapping agent fine-tuning with GRPO

A live Chorus.build org (manager + engineers + analyst + reviewer) was given a single hard goal: build grpo_tune, a pip-installable library that wraps agent fine-tuning with Group-Relative Policy Optimization. This report dissects what the org actually produced — both the deliverable defects and the framework behaviors the run exposed.

goal status: blocked tasks: 22 · done 18 · rejected 2 · blocked 2 deliverable flaws: 9 framework flaws: 5

A. Deliverable flaws — the grpo_tune library

What shipped in main as the "finished" library, and why it isn't one.

1Split-brain: two different, incompatible Trainers

grpo_tune/trainer.py (the package, 773 B) is a stub — Trainer(model, sampler, config).fit() just loops and calls model.update(batch). No GRPO math.

trainer.py (repo root, 2949 B, orphaned) is the real GRPO — Trainer(model=, reward=, config=).fit(Batch) with genuine group-relative advantages (adv = r − mean(group)).

They have incompatible APIs (sampler-based vs. reward+batch-based) and were never reconciled.

CRITICAL · two conflicting implementations of the core class
2The real GRPO code is unreachable

It lives at repo root, outside the grpo_tune/ package, so import grpo_tune can never reach it. The package ships only the stub.

CRITICAL · the actual algorithm is not importable
3The package exports nothing

grpo_tune/__init__.py is 25 bytes ("""grpo_tune package."""). from grpo_tune import Trainer fails — there's no public API. The library is unusable as a library.

CRITICAL · no public surface
4"Tests pass" is an illusion — they test two different universes

The 25 green tests import from both modules:

  • test_trainer_fit_determinism.py → from grpo_tune.trainer import Trainer (the stub)
  • test_trainer_fit_e2e.py, test_trainer_validation_errors.py, test_trainer_error_messages.py → from trainer import … (the root real one)

They only co-pass because pytest puts the repo root on sys.path. pip install grpo_tune → the root trainer.py + 3 of the 5 test files break, and the real GRPO disappears.

CRITICAL · the green suite is an artifact of the dev layout
5A required module is missing from main

grpo_tune/rewards.py. The spec demanded a typed RewardFunction Protocol there. It's absent (the root trainer just calls self.reward(...), typed Any).

CRITICAL · spec-required module never landed (see flaw 10)
6TrainerConfig is defined twice, inconsistently

grpo_tune/config.py (batch_size, steps, lr, seed) vs. root trainer.py (group_size, steps). Conflicting schemas for the same name.

CRITICAL · the config contract is ambiguous
7No packaging

No pyproject.toml / setup.py. The "Python library" can't be installed or distributed.

CRITICAL · not a distributable artifact
8README never written

It's still the seed stub: # company repo. No usage, no install, no GRPO explanation.

HIGH · zero documentation
9Repo polluted with 32 harness-internal files

docs/evals/*.json (10) and docs/exec-plans/*.json/.md (22): dream's own run artifacts scaffolded into the deliverable. Plus a stray root test_smoke.py outside tests/.

HIGH · the kernel's working files leaked into the product

B. Framework / orchestration flaws — chorus behaviors this run exposed

These are not the library's faults; they're kernel/orchestration behaviors made visible by the run.

10A task marked done whose work never landed

t_task_5aeeec0de80e — "Implement grpo_tune/rewards.py" by engineer di — is done in the ledger, but rewards.py is absent from main. The git log shows merges from ada/bo/cy only — never di. So di's whole branch never integrated, yet its tasks read done.

This is a real landing/integration bug: "done" ≠ "landed."

FRAMEWORK · ledger state diverges from the integrated tree
11Manager mis-assigns deliverables to the analyst — twice, both rejected

Both trainer.py implementation tasks went to ana (analyst), who can't write code → both rejected (bae43175155b, 01fca6d7b947). The manager repeated the mistake instead of routing to an engineer.

Exactly the cofounder's known wart, now seen looping.

FRAMEWORK · no role-capability check at assignment
12The goal never closed — ended blocked

Report: 22 tasks → 18 done, 2 rejected, 2 blocked; the top goal (vera) and max's package subtree (fb5191136214) both blocked. The director churned on rewards.py placement and hit the integrate cap / 20-min deadline without a clean done verdict.

FRAMEWORK · integrate churn exhausts the cap before convergence
13"Tests pass but off-brief" — the DoD didn't enforce the actual goal

The package's Command DoD went green on a stub with no GRPO algorithm. This is the documented "objective Command DoD is silently skippable" finding, live: the gate verifies determinism / "update called," not that GRPO is implemented — so shallow, off-brief work passes.

FRAMEWORK · the DoD measures the wrong thing
14No de-duplication / no global file ownership

Parallel engineers each created their own grpo_tune/ + trainer.py (the report shows ~5 near-identical "Create package directory grpo_tune/" tasks by di/cy). Integrate merged fragments without reconciling them → the duplicate trainers and the orphaned real implementation.

FRAMEWORK · no cross-child ownership map → fragments collide
