A. Deliverable flaws — the streamparse deliverable (6)

Defects in what the org actually produced — is it a real, usable, distributable artifact?

1The package entry exports a hello-world placeholder, not the parserENTRY-PLACEHOLDER
src/index.ts — the package main — is exactly `export const hello = 'world' as const;`. The real StreamEvent type and the fold-a-stream-into-events parser live in src/streamParser.ts, but index.ts never re-exports them. `import { ... } from 'streamparse'` yields only `hello`. The brief's entire public surface is unreachable through the entry point.
2tsc does not typecheck — the package does not buildTSC-BROKEN
tsc --noEmit exits rc=2 with error TS2304: Cannot find name 'ReadableStream' (multiple sites). tsconfig sets lib: ["ES2020"], which omits DOM/WebWorker, yet streamParser.ts builds on ReadableStream<Uint8Array>. The required Web-Streams type is used but never made available — so the deliverable fails its own toolchain's build.
3package.json exports reference files the source can never produceFICTIONAL-EXPORTS
package.json declares main: ./dist/index.js and an exports map with ./parser → ./dist/parser.js and ./StreamEvent → ./dist/StreamEvent.js. The source is src/index.ts + src/streamParser.ts — there is no parser.ts or StreamEvent.ts. tsc would emit dist/index.js + dist/streamParser.js, never dist/parser.js or dist/StreamEvent.js. The manifest's public surface is a fiction unrelated to the code.
4The tests are Python and only assert a file existsPYTHON-TESTS
package.json sets "test": "pytest -q" — a Python runner for a TypeScript package — and the test files are Python. test_stream_parser.py in full: `assert pathlib.Path("src/streamParser.ts").exists()`. It never imports, compiles, or exercises the parser; it checks the .ts file is on disk. The brief required vitest feeding canned chunk sequences and asserting reconstructed events. 'Tests pass' here means nothing about the parser's behaviour.
5The package is named after the engineer, not the deliverableWRONG-NAME
package.json "name": "ada" — the id of the engineer whose branch won the manifest — instead of "streamparse". The published package would carry the author's name, not the product's.
6Stray Python files + README stub + leaked harness filesSTRAY
Root test_smoke.py (`assert True`) and test_stream_parser.py — Python files in a TS package. README.md is the 15-byte '# company repo' stub. Harness-internal files leaked (docs/evals/*.json, docs/exec-plans/*).
