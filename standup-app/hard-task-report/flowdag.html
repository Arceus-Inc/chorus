A. Deliverable flaws — the flowdag deliverable (5)

Defects in what the org actually produced — is it a real, usable, distributable artifact?

1The library is implemented twice — once in Go, once in PythonCROSS-LANG-SPLIT-BRAIN
The brief asked for a Go module. The repo ships flowdag.go (12 KB, Go) AND flowdag.py (10 KB, a full Python re-implementation), each with its own tests (flowdag_test.go + dag_skip_test.go vs test_flowdag.py). flowdag.py's own docstring admits the divergence: 'The sprint task asks for flowdag.go; this repository is Python-only (tests run via pytest), so we implement the requested exported API in a Python module.' One engineer wrote Go; another decided the repo was Python and rewrote the whole thing; integrate merged both. This is split-brain across LANGUAGES, not just modules.
2The Go module does not compileGO-BUILD-BROKEN
`go build ./...` fails rc=1: flowdag.go:520:29: syntax error: method must have no type parameters. The code declares `func (r *Resolver) ResolveAs[T any](ctx, taskID) (T, error)` — Go does not allow type parameters on methods (generic methods are unsupported). The required deliverable — the Go module — is not buildable.
3go test fails (build failed)GO-TEST-BROKEN
`go test ./...` exits rc=1 with 'FAIL flowdag [build failed]' — the same syntax error blocks the test binary. The Go test suite (flowdag_test.go, dag_skip_test.go) cannot run at all.
4The DoD validated the Python rival, not the Go deliverableWRONG-DOD-TARGET
The objective gate ran pytest (test_flowdag.py imports the Python flowdag), which passes — while `go build` of the actual brief deliverable fails to compile. The org's DoD checked the wrong language entirely, so a non-compiling Go module passed because its accidental Python twin's tests were green. (Same wrong-toolchain failure mode as the streamparse run.)
5README stub + stray smoke test + leaked harness filesSTRAY
README.md is the 15-byte '# company repo' stub. Root test_smoke.py (`assert True`) is committed. Harness-internal files leaked (docs/evals/*.json, docs/exec-plans/*).
