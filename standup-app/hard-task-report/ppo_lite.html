A. Deliverable flaws — the ppo_lite deliverable (8)

Defects in what the org actually produced — is it a real, usable, distributable artifact?

1import ppo_lite crashes on a clean install — the package can't even be loadedIMPORT-BROKEN
ppo_lite/__init__.py eagerly does `from .gae import compute_gae`, and gae.py does a top-level `import numpy` (and torch). numpy/torch are declared in NO manifest. In a clean environment `import ppo_lite` raises ModuleNotFoundError: No module named 'numpy'. The probe's `pytest -q` exits rc=2 — a COLLECTION error, not a test failure: tests/test_losses.py can't import the package at all. The org's reviewed DoD passed only because the engineer worktrees happened to have numpy/torch installed; the landed deliverable is import-broken.
2The train(env) loop is REINFORCE, not PPONOT-PPO
train() in train.py computes loss = -(logp * reward) — a one-step vanilla policy gradient on the immediate reward. It never calls ppo_losses, never uses the clipped surrogate objective, never uses GAE advantages, and never touches the RolloutBuffer. The brief's single headline deliverable — a PPO train loop — does not implement PPO. The three real PPO pieces sit in the repo unused.
3GAE is implemented twice, in two incompatible numeric substratesGAE-TWICE
gae.py::compute_gae implements GAE in torch (returns torch.FloatTensor). buffer.py::RolloutBuffer.compute_returns_and_advantages re-implements the identical GAE recursion in numpy (plus advantage normalization). Two independent copies of the same algorithm; buffer.py never calls compute_gae. Both recursions are individually correct — which makes the duplication purely an integration failure, not a math error.
4The three brief-required surfaces are not exportedEXPORTS
__init__ exports only PPOConfig, compute_gae, seed_everything. The clipped surrogate (ppo_losses), the rollout buffer (RolloutBuffer), and the train loop (train) — the three things the brief explicitly required — are NOT in __all__ and not imported into the package namespace. `from ppo_lite import ppo_losses / RolloutBuffer / train` all fail; a user must reach into private submodules.
5PPOConfig (all the PPO hyperparameters) is exported but unused; train uses a different configDEAD-PPOCONFIG
config.py defines PPOConfig with gamma, gae_lambda, clip_coef, vf_coef, ent_coef, lr, update_epochs, minibatch_size… But train() takes a separate TrainConfig(seed, total_steps, lr) and ignores PPOConfig entirely. So every PPO knob is dead. There's also a name mismatch: PPOConfig.clip_coef vs ppo_losses(clip_range=…) — they wouldn't line up even if someone tried to wire them.
6Four components, three numeric substrates — they don't composeSUBSTRATE-SPLIT
gae.py and train.py are torch; losses.py is pure-Python floats (its docstring: “dependency-free … minimal environments”); buffer.py is numpy. compute_gae emits torch tensors while ppo_losses consumes float lists — you cannot feed one into the other without manual conversion. Each engineer picked a different substrate and nothing reconciled them.
7No packaging and undeclared heavy dependenciesPKG
No pyproject.toml / setup.py / setup.cfg of any kind. The package imports torch (gae.py, train.py) and numpy (gae.py, buffer.py) but declares neither. It is neither installable nor reproducible.
8README stub + stray + leaked filesSTRAY
README.md is the 15-byte seed stub “# company repo”. Root test_smoke.py (`assert True`) sits outside tests/. ~24 harness-internal files leaked (docs/evals/*.json, docs/exec-plans/*).
